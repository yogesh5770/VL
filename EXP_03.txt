================================================================================
EXPERIMENT 3: COLD MIGRATION OF VIRTUAL MACHINE FROM ONE HOST TO ANOTHER
              (USING EXPORT / IMPORT APPLIANCE - OVA METHOD)
================================================================================

AIM:
To perform cold migration of a Virtual Machine (VM) from a Source Host to a Destination
Host using the VirtualBox Export and Import Appliance method (Open Virtualization Format / OVA)
while the VM is in a powered-off state, and verify configuration and data integrity.

PREREQUISITES:
1. Source Physical Machine with Oracle VM VirtualBox installed and an existing VM.
2. Destination Physical Machine with Oracle VM VirtualBox installed.
3. Intermediate storage medium (USB drive / external hard drive / shared network drive)
   with sufficient free disk space to store the exported appliance (.ova file).
4. Both host machines must have virtualization enabled in BIOS.

THEORY / CORE CONCEPTS:
- What is Cold Migration?
  Cold migration is the migration of a powered-off virtual machine from one host to another.
  During cold migration, the VM's disk image (VDI/VMDK) and hardware configuration XML files
  are packaged and transferred. Because the VM is offline, there is zero risk of data
  corruption during state transfer, but downtime occurs.
- OVA vs OVF:
  * OVF (Open Virtualization Format): A directory containing multiple files (.ovf descriptor,
    .mf manifest, and .vmdk disk files).
  * OVA (Open Virtualization Appliance): A single compressed TAR archive containing all OVF
    files packaged together into a single file (.ova), making it portable and easy to share.

--------------------------------------------------------------------------------
STEP-BY-STEP PROCEDURE:
--------------------------------------------------------------------------------

PHASE 1: PREPARATION & CREATING DATA MARKER (ON SOURCE HOST)
STEP 1: Boot the VM on the Source Host and create a unique test file to verify data integrity post-migration.
1. Start the VM (Ubuntu) on the Source Machine.
2. Open Terminal and execute:
   $ cd ~
   $ echo "=== COLD MIGRATION VERIFICATION FILE ===" > migration_verify.txt
   $ echo "Created on Source Host at: $(date)" >> migration_verify.txt
   $ cat migration_verify.txt
3. Alternatively create a Java test file:
   $ echo 'public class Test { public static void main(String[] args){ System.out.println("Migrated VM is Working!"); }}' > test.java
   $ cat test.java
4. Gracefully power off the VM:
   $ sudo shutdown -h now
   (Or from VirtualBox GUI: Machine -> ACPI Shutdown / Power Off).

PHASE 2: EXPORTING APPLIANCE FROM SOURCE HOST (VIRTUALBOX GUI)
STEP 2: Open VirtualBox Manager on the Source Host.
STEP 3: Select the powered-off VM from the left list.
STEP 4: Go to Menu Bar: Click "File" -> "Export Appliance..." (or press Ctrl + E).
STEP 5: In the Export Virtual Appliance wizard:
   - "Virtual machines": Verify your target VM is selected -> Click "Next".
   - "Format": Select "Open Virtualization Format 1.0" (or 2.0).
   - "File": Click the folder icon and specify the destination path and file name:
     e.g., D:\ColdMigration\Ubuntu_Migrated.ova (or directly to your USB drive).
   - "MAC Address Policy": Select "Include only NAT network adapter MAC addresses"
     (or "Include all network adapter MAC addresses").
STEP 6: Click "Next", review the appliance settings (Name, CPU, RAM), and click "Finish" (or "Export").
STEP 7: Wait for the progress bar to complete. (VirtualBox will compress the virtual disk into the single .ova file).

PHASE 3: TRANSFERRING THE APPLIANCE
STEP 8: Locate the generated `Ubuntu_Migrated.ova` file on the Source Machine.
STEP 9: Copy `Ubuntu_Migrated.ova` to an external USB Flash Drive / Portable SSD or transfer
        over LAN via SCP/FTP.
STEP 10: Safely eject the USB drive from Source Host and plug it into the Destination Host.
STEP 11: Copy `Ubuntu_Migrated.ova` from the USB drive to a local drive on the Destination Host (e.g., D:\VMs\).

PHASE 4: IMPORTING APPLIANCE ON DESTINATION HOST
STEP 12: Open Oracle VM VirtualBox Manager on the Destination Host.
STEP 13: Go to Menu Bar: Click "File" -> "Import Appliance..." (or press Ctrl + I).
STEP 14: Click the folder browse icon, navigate to the `Ubuntu_Migrated.ova` file, and click "Open".
STEP 15: Click "Next".
STEP 16: In "Appliance Settings":
   - Verify CPU and RAM allocations.
   - "Machine Base Folder": Set the folder where the VM should be extracted (e.g., C:\VirtualBox VMs\).
   - "MAC Address Policy": Select "Generate new MAC addresses for all network adapters"
     (prevents MAC address collision if both VMs ever run on the same LAN).
STEP 17: Click "Finish" (or "Import") and accept software license agreements if prompted.
STEP 18: Wait for the import progress bar to reach 100%.

PHASE 5: VERIFICATION ON DESTINATION HOST
STEP 19: The newly migrated VM will now appear in the VirtualBox Manager list.
STEP 20: Select the imported VM and click "Start" (Green Arrow).
STEP 21: Log in with the same user credentials used on the Source Host.
STEP 22: Open Terminal (Ctrl + Alt + T) and verify the test marker file:
   $ cat ~/migration_verify.txt
   $ cat ~/test.java
   $ javac test.java && java Test
STEP 23: Observe that all files, directories, installed packages, user configurations,
         and disk contents have been preserved completely.

--------------------------------------------------------------------------------
VIVA VOCE QUESTIONS & ANSWERS:
--------------------------------------------------------------------------------
Q1: What is the key difference between Cold Migration, Warm Migration, and Live Migration?
A1:
- Cold Migration: The VM is completely shut down (powered off) before migration. Incurs downtime, but simple and requires no shared storage.
- Warm Migration: The VM continues running while preliminary disk sync occurs; VM is briefly paused to sync remaining delta and resumed on destination.
- Live Migration (Hot Migration): The VM remains actively powered on and executing tasks with zero perceived downtime; memory pages and CPU registers are synchronized across hosts over high-speed networks and shared storage.

Q2: What is an OVA file? How does it differ from OVF?
A2: An OVF (Open Virtualization Format) is an open-standard package consisting of separate descriptor (.ovf), manifest (.mf), and virtual disk (.vmdk) files. An OVA (Open Virtualization Appliance) is a single, self-contained TAR archive packaging all OVF components together.

Q3: Why should you generate new MAC addresses when importing an appliance?
A3: If the source VM and migrated VM are ever powered on simultaneously within the same local network subnet, duplicate MAC addresses will cause ARP spoofing conflicts, packet collisions, and broken network connectivity.

Q4: What happens to the VM's active RAM state during Cold Migration?
A4: During cold migration, volatile RAM state is cleared upon normal shutdown. Only persistent storage (virtual hard disks) and VM hardware configuration definitions are transferred.

--------------------------------------------------------------------------------
RESULT:
--------------------------------------------------------------------------------
The virtual machine was successfully migrated from the source host to the destination host
in a powered-off state (Cold Migration) using the OVA export/import appliance method.
The hardware configuration, system state, and data files were verified intact on the
destination host without any data corruption.
