================================================================================
EXPERIMENT 4a: INSTALLATION OF CITRIX XENSERVER
EXPERIMENT 4b: LIVE MIGRATION OF A RUNNING VM USING XENCENTER
================================================================================

AIM:
1. To install Citrix XenServer (Type 1 Bare-Metal Hypervisor) on a physical server.
2. To move (Live Migrate) a running Virtual Machine from Server 1 to Server 2 
   using XenCenter with ZERO downtime (the VM never stops running).

WHAT IS CITRIX XENSERVER?
It is a Type-1 (Bare-Metal) hypervisor that runs directly on computer hardware without Windows/Linux.

WHAT IS XENCENTER?
It is a Windows desktop application (GUI) used to control and manage XenServer.

WHAT IS LIVE MIGRATION?
Moving a live, running virtual machine from one physical server to another while it is still working,
without shutting it down and without losing any data.

--------------------------------------------------------------------------------
STEP-BY-STEP PROCEDURE (4a - INSTALL CITRIX XENSERVER):
--------------------------------------------------------------------------------

STEP 1: Make Bootable USB
1. Download XenServer ISO file.
2. Open Rufus on Windows, select your USB drive and the XenServer ISO -> Click Start to make bootable USB.

STEP 2: Server BIOS Setup
1. Plug USB into the server computer and turn it on.
2. Press F2 or Del key to enter BIOS.
3. Turn ON "Intel Virtualization Technology" (VT-x) or "AMD-V".
4. Set USB as 1st boot device -> Save and Restart.

STEP 3: Install XenServer on Server
1. The XenServer installer screen opens -> Press Enter.
2. Select US Keyboard -> Click OK -> Accept License Agreement (EULA).
3. Select your hard disk drive to install XenServer.
4. Set a root password (e.g., Password123) and remember it!
5. Choose Network Settings -> Select Static IP:
   - IP Address: 192.168.1.50
   - Subnet Mask: 255.255.255.0
   - Gateway: 192.168.1.1
6. Click "Install XenServer".
7. After installation completes, remove the USB drive and click "Reboot".
8. When the server turns on, you will see a black and yellow screen showing the server IP: 192.168.1.50.
   (XenServer is now successfully installed!).

--------------------------------------------------------------------------------
STEP-BY-STEP PROCEDURE (4b - LIVE MIGRATION USING XENCENTER):
--------------------------------------------------------------------------------

REQUIREMENTS FOR LIVE MIGRATION:
1. Server 1 and Server 2 must be connected on the same network.
2. Both servers must share a common storage (NFS or iSCSI shared storage folder).
3. Both servers must have similar CPUs.

STEP 1: Open XenCenter
1. On your Windows computer, open the XenCenter app.

STEP 2: Add Both Servers to XenCenter
1. Click menu: "Server" -> "Add" (or press Ctrl + Shift + A).
   - Server: 192.168.1.50 (Server 1)
   - User name: root
   - Password: Password123
   - Click "Add".
2. Click "Server" -> "Add" again:
   - Server: 192.168.1.51 (Server 2)
   - User name: root
   - Password: Password123
   - Click "Add".
-> Now you can see Server 1 and Server 2 on the left side menu!

STEP 3: Add Shared Storage (NFS)
1. In XenCenter, click "Storage" -> "New SR" (New Storage Repository).
2. Choose "NFS VHD" -> Click "Next".
3. Name: "MySharedNFS" -> Click "Next".
4. Enter your shared folder path: e.g. 192.168.1.100:/srv/nfs
5. Click "Finish".
-> Now both Server 1 and Server 2 can access this shared storage!

STEP 4: Create a Virtual Machine on Server 1
1. Right-click Server 1 -> Click "New VM...".
2. Template: Select "Ubuntu" -> Give name "Test_VM".
3. Under Storage: Select "MySharedNFS" (the shared storage).
4. Memory: 2 GB (2048 MB) -> Click "Create Now".
5. Turn ON the VM.

STEP 5: Start a Workload (Proof of Zero Downtime)
1. Click the VM -> Click "Console" tab.
2. Type:
   ping 8.8.8.8
   (It will keep printing ping replies continuously).

STEP 6: Perform Live Migration (The Magic Step!)
1. Right-click the running "Test_VM" under Server 1.
2. Click "Move VM..." (or "Migrate to Server").
3. Select Destination: Click "Server 2" (192.168.1.51).
4. Click "Finish".
5. Watch the screen: The VM moves from Server 1 to Server 2.
6. Look at the Console tab: The ping 8.8.8.8 is STILL running without stopping!
   Zero packets lost! Zero seconds downtime!

--------------------------------------------------------------------------------
SUPER SIMPLE VIVA QUESTIONS:
--------------------------------------------------------------------------------
Q1: What is Type 1 Hypervisor vs Type 2 Hypervisor?
A:
- Type 1: Runs directly on bare-metal hardware with no host OS (e.g., XenServer, KVM, ESXi). Very fast.
- Type 2: Runs as software on top of an existing OS like Windows (e.g., VirtualBox).

Q2: What is Dom0 in Xen?
A: Dom0 is the special control virtual machine that has driver access and manages all other guest VMs.

Q3: Why do we need Shared Storage for Live Migration?
A: Because moving 50 GB hard disks takes too long. If both servers share the same hard disk, only the RAM (memory) needs to be transferred across the network.

Citrix XenServer was successfully installed on physical hardware. Live Migration of a running
